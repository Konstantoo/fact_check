# Исследование рынка: простой «верификатор» утверждений (сентябрь 2026)

Контекст: в репозитории `/home/user/fact_check` уже есть Telegram-бот на Python (python-telegram-bot 20.7, aiohttp), который ходит в Perplexity (`sonar` для быстрой проверки, `sonar-deep-research` для «Deep Research»), имеет 5-этапный «профессиональный» фактчек (`services/professional_factchecker_service.py`, 5 последовательных вызовов Sonar), эвристический рейтинг доменов (`services/source_validator_service.py`), дневные лимиты и заглушку оплаты через ЮKassa. Важно: `main.py` импортирует модули, которых в репозитории нет (`storage/`, `worker.py`, `services/message_delivery_service.py`, `services/professional_editor_service.py`, `utils/professional_response_formatter.py`) — в текущем виде бот не запустится; это отдельная задача, не относящаяся к MVP.

---

## 1. Резюме

1. **Спрос огромен, доверие низкое.** «@grok is this true?» стал самым частым запросом к Grok: ~1,4 млн запросов на фактчек к Grok и Perplexity за полгода. При этом Grok совпал с вердиктами живых фактчекеров лишь в 54,5 % случаев, а 21–28 % постов, помеченных Community Notes как ложные, ИИ-боты назвали правдой. Аудит NewsGuard (январь 2026): 11 ведущих чат-ботов повторяют ложные утверждения в >28 % случаев и способны выдумывать «экспертов» по запросу.
2. **Главные жалобы пользователей** одинаковы во всех обзорах: (а) выдуманные/нерабочие ссылки, (б) уверенный тон без степени уверенности, (в) медленно (deep-режимы по 1–5 минут), (г) ответ без источников или с «паразитными» источниками (агрегаторы, SEO-мусор), (д) ошибки на свежих новостях и на неанглийском контенте.
3. **Русскоязычная ниша почти пуста.** Институциональные проекты («Лапша Медиа» — ответ до суток, ручная проверка; «Проверено.Медиа» — только бот для предложения тем) не дают мгновенного вердикта. Коммерческие RU-«фактчекеры» (AI Pisaka, Syntx AI, Yes AI, Neurs AI, StudyAI, UseGPT и др.) — это обёртки над ChatGPT без веб-поиска и без ссылок: они ищут «противоречия в тексте», а не проверяют факты по источникам. Ни у одного нет формата «вердикт + уверенность + 3–5 живых ссылок».
4. **Западный эталон «простого верификатора» уже существует** — FactGuard (одно поле ввода → вердикт True/False/Mostly True/Mixed, калиброванная уверенность 0–100 %, ссылки на первоисточники, короткое объяснение; 3 бесплатных проверки/день, Pro $4.99/мес). Русскоязычного аналога нет — это и есть ниша.
5. **Стоимость одной проверки на API — 1–4 ₽** при разумной архитектуре (один вызов Perplexity `sonar` ≈ $0,008–0,015; OpenAI gpt-5-nano + web search ≈ $0,011; Anthropic web search $0,01/поиск + токены). Google Fact Check Tools API бесплатен и покрывает часть русскоязычных ClaimReview — идеален как «нулевой», мгновенный слой.
6. **Текущий код избыточен для MVP:** 5 последовательных Sonar-вызовов в «профессиональном» режиме — это ×5 стоимость и ×5 задержка без роста точности. Для MVP достаточно одного вызова с JSON-схемой + проверки живости ссылок (HEAD-запрос), которая в репозитории уже есть.
7. **Рекомендация:** MVP = одна команда/один экран «вставь утверждение → вердикт (Правда / Ложь / Скорее правда / Скорее ложь / Не проверяемо) + уверенность + 3–5 проверенных ссылок + одна строка объяснения», реализованный как тонкий модуль `services/verifier_service.py` с двумя фронтами: Telegram-команда (переиспользуем бот) и одностраничный FastAPI + HTML (для шаринга ссылкой). Streamlit — только для внутренней демонстрации.

## 3. UX-паттерны минимального верификатора

**Устоявшийся паттерн (FactGuard, Perplexity Fact Checker CLI, Snopes FactBot, академические системы Althea/FinVet):**

1. **Один вход** — поле «вставьте утверждение, заголовок или ссылку». Без выбора режимов до первого результата (у нашего бота сейчас меню из 4 кнопок — лишний шаг).
2. **Вердикт как шкала, а не бинарный флаг.** Используемые наборы: `TRUE / FALSE / MISLEADING / UNVERIFIABLE` (Perplexity), `True / Mostly True / Mixed / False` (FactGuard), `Правда / В основном правда / Полуправда / В основном неправда / Неправда / Не проверяемо` (Проверено.Медиа, IFCN-стиль). Для RU MVP: **Правда · Скорее правда · Смешанно · Скорее ложь · Ложь · Нельзя проверить** + цветовой код.
3. **Уверенность** — число 0–100 % или три уровня (низкая/средняя/высокая). Исследования (Explaining Sources of Uncertainty in Automated Fact-Checking, 2025) показывают: пользователи доверяют больше, когда уверенность сопровождается **причиной** («мало независимых источников», «источники противоречат», «утверждение слишком расплывчато»).
4. **3–5 источников** с заголовком, доменом, датой и **цитатой** (`cited_text`), а не просто URL. Ссылки должны быть проверены на HTTP-живость до показа — главная жалоба на ИИ-фактчекеры именно «мёртвые/выдуманные ссылки».
5. **Одна строка объяснения** («Почему так»): 1–2 предложения. Подробности — по кнопке «Подробнее» / раскрывающийся блок.
6. **Честное «не знаю».** Snopes FactBot явно отвечает «недостаточно данных» вместо галлюцинации; это повышает доверие. Вердикт «Нельзя проверить» должен быть первоклассным исходом, а не ошибкой.
7. **Скорость и её ожидание.** Норма пользователя — 3–8 секунд. Для Telegram — сообщение «Проверяю…» и редактирование того же сообщения; для веба — скелетон/прогресс. Deep-режимы (минуты) оставлять как отдельную платную кнопку после быстрого вердикта, как сейчас сделано в боте.
8. **Шаримость.** FactGuard выпускает «карточки вердикта»; в Telegram — компактное сообщение, которое удобно переслать в чат, где появился фейк. Это основной канал роста для RU-аудитории.
9. **Стабильный формат ответа** (одинаковая структура каждый раз) важнее «красивого текста»: пользователи сканируют глазами вердикт → уверенность → ссылки.

**На что жалуются (сводка Reddit/Twitter/GitHub, Poynter, Axios, NewsGuard, vc.ru/DTF):**
- выдуманные цитаты и эксперты; ссылки на несуществующие страницы;
- «уверенно, но неправильно» — нет сигнала неопределённости;
- медленно и дорого в deep-режимах; лимиты и троттлинг на бесплатных планах;
- ответ меняется в зависимости от геолокации/формулировки (Poynter);
- на русском: «шаблонные замечания», ограничение объёма, «проверяет логику, а не факты»;
- необходимость всё перепроверять вручную «съедает» сэкономленное время.

**Оценка юнит-экономики MVP:** при 1 вызове `sonar` (low) + бесплатном Google Fact Check + HEAD-проверке ссылок — ~1 ₽ за проверку; 1 000 проверок ≈ 1 000 ₽/мес. Бесплатный лимит 3–5 проверок/день на пользователя (как у FactGuard) и платный пакет 199–299 ₽/мес окупаются уже при ~5 % конверсии.

## 5. Ниша и рекомендуемый MVP

### 5.1. Где пробел

- **Русскоязычный «мгновенный вердикт со ссылками»** — не существует. Институциональные фактчекеры медленные, коммерческие RU-боты без поиска.
- **Калиброванная уверенность + причина неопределённости** — нет ни у одного RU-сервиса и почти ни у кого глобально (кроме FactGuard/академических).
- **Гарантия живых ссылок** (проверка HTTP-статуса + вес домена) — прямой ответ на главную жалобу; в репозитории уже есть `SourceValidatorService` с рейтингом доменов и `_check_url`.
- **Слой готовых фактчеков** (Google Fact Check API + собственный кэш вердиктов) — даёт мгновенный ответ на «вирусные» фейки и снижает расходы.
- **Шаримая карточка в Telegram** — вирусный канал, которого нет у веб-сервисов.

### 5.2. Что НЕ делать в MVP
- 5-ступенчатые «профессиональные» пайплайны (текущий `professional_factchecker_service.py`): ×5 стоимость/латентность без доказанного роста точности.
- Анализ видео/скриншотов (OCR) — вторая итерация.
- Собственную базу вердиктов с ручной модерацией — позже.

### 5.3. Рекомендуемый scope MVP (один экран)

**Вход:** одно текстовое поле — утверждение или ссылка (ссылка → извлечь заголовок/первый абзац, как сейчас делает `_prefetch_article_text`). Лимит 1 000 символов.

**Пайплайн (цель ≤ 8 с):**
1. Нормализовать утверждение (обрезать, определить язык).
2. Параллельно: (а) Google Fact Check API `claims:search?query=...&languageCode=ru`; (б) один вызов Perplexity `sonar` с `search_context_size=low`, системным промптом фактчекера и JSON-схемой:
   ```json
   {"verdict": "true|mostly_true|mixed|mostly_false|false|unverifiable",
    "confidence": 0-100,
    "confidence_reason": "строка",
    "explanation": "одна строка на русском",
    "sources": [{"url": "...", "title": "...", "quote": "...", "date": "..."}]}
   ```
3. Пост-обработка: HEAD/GET-проверка каждой ссылки (2 с таймаут), отбросить мёртвые, отсортировать по рейтингу домена (`SourceValidatorService`), оставить 3–5. Если живых источников < 2 — понизить уверенность и/или заменить вердикт на «Нельзя проверить».
4. Если Google Fact Check вернул совпадение — показать его первым блоком «Уже проверяли: <издание> — <вердикт>».
5. Кэш ответа по нормализованному тексту (SQLite, 7 дней) — повторные вирусные утверждения бесплатны.

**Выход (единый шаблон):**
```
🟥 ЛОЖЬ · уверенность 85 %
Утверждение: «…»
Почему: одна строка.
Источники:
1. Название — домен, дата
2. …
3. …
ℹ️ Уверенность снижена: источники расходятся / мало независимых источников
[Проверить глубже (платно)] [Поделиться]
```
Цвета: 🟩 правда, 🟨 смешанно/скорее, 🟥 ложь, ⬜ нельзя проверить.

**Лимиты и монетизация:** 3–5 проверок/день бесплатно; пакет проверок или подписка (ЮKassa уже заложена в конфиг); «Глубокая проверка» (`sonar-pro`/`sonar-deep-research`) — платная кнопка.

**Метрики MVP:** доля ответов с ≥3 живыми ссылками, p50/p95 латентность, доля «Нельзя проверить», доля пересылок (share) в Telegram, ручная выборочная оценка 50 вердиктов против Проверено.Медиа/Лапши.

### 5.4. Рекомендуемый стек

| Вариант | Плюсы | Минусы | Рекомендация |
|---|---|---|---|
| **A. Команда/режим в существующем Telegram-боте** (python-telegram-bot 20.7) | Переиспользуем бот, лимиты, оплату, `SourceValidatorService`; аудитория уже в Telegram; шаринг «из коробки» | Нужно починить отсутствующие модули или вынести MVP в отдельный минимальный `bot_min.py`; нет публичной ссылки для веба | **Основной фронт.** Сделать `services/verifier_service.py` (чистая функция `verify(text) -> VerdictDTO`) и тонкий хендлер: любое текстовое сообщение → вердикт, без меню. |
| **B. Одностраничный веб: FastAPI + один HTML (htmx/vanilla JS)** | Публичная ссылка, SEO, легко поделиться, тот же `verifier_service`; FastAPI async совместим с aiohttp-кодом; деплой на тот же Railway | Немного больше кода (форма, шаблон, rate-limit по IP) | **Второй фронт** на том же сервисе: `/` (форма) и `POST /api/verify`. Бот и веб делят один модуль и один кэш. |
| **C. Streamlit** | Самый быстрый прототип (30 строк) | Плохо для публичного продукта (сессии, мобильная вёрстка, нельзя встроить в бот), отдельный процесс | Только для внутренней демонстрации промптов/схем; не как продукт. |

**Итог:** Python 3.11, `aiohttp` (уже есть) для Perplexity/Google/HEAD-проверок, `pydantic` для схемы вердикта, SQLite-кэш, `python-telegram-bot` для фронта A, `FastAPI + uvicorn + Jinja2` для фронта B, единый `Procfile`/`railway.toml`. Провайдер по умолчанию — Perplexity `sonar` (ключ уже есть); абстракция `SearchProvider`, чтобы позже подключить Anthropic web search или связку «Perplexity Search API + GigaChat» для пользователей из РФ.
